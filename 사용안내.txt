시민과학 연구 계획서 영어 세특 — 최종 코드 사용 안내
작성일: 2026-10-11 (한국 시간)

설치와 기본 사용
1. 구글 스프레드시트에서 확장 프로그램 → Apps Script를 연다.
2. 기존 세특 코드 전체를 Code.gs 내용으로 교체한다. 기존 코드 뒤에 추가하지 않는다.
   CONFIG, PROVIDERS, onOpen 및 함수가 중복되지 않도록 한다.
   기존 '1학기 영어 세특 프롬프트.txt'와 처음 첨부한 원본은 수정하지 않았다.
3. 저장하고 스프레드시트를 새로고침한다.
4. 새 메뉴의 설정창에서 Gemini를 선택하고 API 키를 저장한다.
   키 입력란이 비어 있으면 해당 제공사의 기존 키를 유지한다.
5. 학생 행을 선택하고 '① 선택한 행 Gemini 3.8 생성'을 누른다.
   또는 '② 범위 입력 Gemini 3.8 생성'에서 U3:U30, 3:30, U3, 3 등의 범위를 입력한다.
6. 먼저 몇 명을 생성하여 원문과 대조한 뒤 범위를 늘린다.
기본 생성은 항상 gemini-3.8-flash이다. 과거 PROVIDER나 GEMINI_MODEL 설정과 무관하다.
우수 학생을 자동 선별하지 않는다. 교사가 직접 선택한다.

나중에 우수 학생만 Sol로 다시 작성
1. 설정창에서 OpenAI를 선택하고 OpenAI API 키를 저장한다.
   Gemini 키 및 Codex/ChatGPT 로그인과 별개이다.
2. 학생 자료 시트에서 다시 작성할 행의 셀을 선택한다.
   Ctrl을 누른 채 여러 셀이나 범위를 선택하면 떨어진 학생도 처리한다.
   선택한 셀의 열은 상관없으며 해당 행만 처리한다. 중복 행은 한 번 처리한다.
3. '④ 선택한 행만 Sol로 다시 작성'을 누른다. 모델은 gpt-6-sol로 고정된다.
   원문의 강점을 정밀하게 읽도록 하되 칭찬의 강도를 자동으로 높이지 않는다.
4. 기존 U·V가 있으면 '세특 재작성 기록' 시트에 이전 결과와 새 결과를 기록한다.
   시각, 원본 시트 ID·이름, 학생 행, 모델, 이전·새 결과와 바이트를 저장한다.
   학생 원문과 API 키는 기록 시트에 넣지 않는다. 이 시트의 제목 행은 변경하지 않는다.
   백업이 실패하면 기존 U·V도 덮어쓰지 않는다.
5. 이후 ①·②를 누르면 다시 Gemini 3.8이다. 제공사 설정을 되돌릴 필요가 없다.

문체와 원문 근거
두 모델은 같은 작성 프롬프트, 첫 문장, 전개 순서, 종결 규칙과 검증을 사용한다.
무작위 문체 선택을 제거했다. 연구 주제 → 계획 내용 → 확인되는 영어 표현 평가 순서이다.
첫 문장은 '영작 수행평가에서 시민과학과 연계한 [연구 주제] 연구 계획서를 영작함.'으로 조립한다.
한국어 한 문단과 명사형 종결을 사용한다. 근거용 영어 인용은 최종 셀에 넣지 않는다.
작성 규칙은 동일하지만 모델별 어휘까지 완전히 같아지는 것은 아니다.
M열 기존 말하기·듣기 세특은 그대로 합치므로 그 부분의 문체는 바꾸지 않는다.

주제와 각 문장에 원문 근거 구절을 받는다. 코드가 원문에 인용이 실제로 있는지 확인한다.
이후 별도 AI 요청으로 문장 전체의 의미가 원문과 입력 점수에 의해 뒷받침되는지 검증한다.
계획을 실제 연구 수행·달성한 성과로 바꾸거나, 상식으로 조사 도구·방법·효과를 추가하면 반려하도록 했다.
영어 구문 사용을 칭찬하려면 원문에 해당 표현이 있어야 한다. Q=3만으로 없는 구문을 만들지 않는다.
원문과 점수가 충돌하면 해당 칭찬을 생략한다.
분량이 많다는 이유만으로 문법 정확성, 협력 경험이나 실제 연구 성과를 단정하지 않는다.
주제만 있으면 첫 문장만 기록할 수 있다. 목표 분량 하한을 맞추려고 내용을 늘리지 않는다.
내용 검증도 AI이므로 모든 해석 오류를 완전히 제거한다고 보장하지 않는다. 최종 입력 전 원문과 대조한다.

열 배치와 채점표
M 말하기·듣기 세특, N 참고 바이트, O 학생 영작, P 공식 단어 수,
Q 목표 언어 점수(1/2/3), R 문법·표기 점수(1/1.5/2), S 문장 수,
T 기입 수준, U 통합 결과, V 통합 바이트.
학생 자료 시트에는 U·V만 기록한다. M~T의 값과 수식은 다시 쓰지 않는다.
P가 비어 있을 때만 원문에서 영어 단어를 참고 계산한다. 공식 집계가 있으면 P에 입력한다.
내용 점수 열이 없으면 설정의 내용 점수 열 항목을 비워 둔다.
있다면 주제·동기, 필요성, 탐구·시민과학, 어려움·해결, 효과·기여 순서의 열 5개를 연결한다.
각 내용 점수는 1 또는 2이다. 빈칸은 미입력으로 취급한다.
목표 구문은 If it had not been for 가정법과 복합 관계대명사이다.
문법 2점도 오류 3개까지 가능하므로 '문법 오류 없이'라고 단정하지 않는다.
전체 5문장 이하이면 문법 점수 1점이라는 채점 조건도 반영했다.
100단어 이상/70~99단어/69단어 이하의 시험 분량 조건과 기존 세특 분량 구간을 안내한다.
단어 수를 간접 평가 지표로 쓰는 기존 방침은 유지하되 원문보다 평가를 부풀리지 않는다.

기입 정책과 실패 처리
T가 부정행위 또는 미제출이면 U를 강제로 비우고 V=0으로 기록한다. M도 합치지 않는다.
T가 참가함이면 활동 참가 고정 문장만 기록한다. M도 합치지 않는다.
이 두 처리는 API 설정이 없어도 실행한다.
100단어 미만 또는 69단어 이하라는 이유만으로 참가 처리하지 않는다.
제출 원문에서 연구 주제와 평가할 내용 자체가 전혀 확인되지 않을 때만 참가 문장을 선택할 수 있다.
AI가 참가 문장을 선택한 경우에도 내용 검증을 거친다.
일반 결과는 작문 세특 + 공백 + M열 세특이다.
O가 빈칸이면 API를 호출하지 않고 기존 U·V를 유지하며 건너뛴 건수로 안내한다.
빈칸 행의 기존 결과도 지우려면 T에 미제출을 입력한다.
API 실패·검증 실패는 기존 U·V를 유지하고 해당 행을 재개 목록에 남긴다.
확인되지 않은 초안이나 오류 문구를 정상 결과로 저장하지 않는다.

바이트와 API 요청
전체 상한 1,500바이트에서 M열과 연결 공백을 실제로 차감한다. 최소 500바이트 강제 배정은 제거했다.
일반 단어 일부를 '풍부한 분량으로'로 치환하던 처리는 제거했다.
길이가 넘으면 완결된 문장까지 남긴 뒤 실제 저장할 문장을 검증한다.
단어·조사 중간을 자르지 않는다. 첫 문장조차 들어가지 않으면 저장하지 않고 오류로 안내한다.
정상 AI 생성은 학생당 작성 1회 + 내용 검증 1회, 보통 2회의 API 요청이다.
보정은 최대 1회이다. 보정 뒤 다시 검증하면 총 4회까지 요청한다. HTTP 오류 재시도는 별도이다.
로컬 형식·인용·바이트 검사는 토큰을 쓰지 않지만 별도 AI 검증은 토큰과 비용을 사용한다.
부정행위·미제출·T=참가함·원문 빈칸은 AI를 호출하지 않는다.
MAX_OUTPUT_TOKENS=3000은 요청별 출력 상한이며 실제 소비량이나 바이트 수가 아니다.
사고 토큰으로 상한을 소진하면 출력이 중단될 수 있다.
MAX_TOKENS 또는 incomplete로 끝난 응답은 정상 저장하지 않는다.

중단과 재개
약 4분이 지나면 다음 API 호출 전에 중단한다. 성공한 학생의 결과는 행마다 즉시 저장한다.
'③ 중단·실패한 행 이어서 처리'는 원래 시트, 남은 행, 원래 모델을 유지한다.
Sol 작업은 설정창을 바꿔도 Sol로 재개한다.
재개 목록은 최근 작업 하나이다. 새 작업을 시작하면 이전 재개 목록이 교체된다.
한 번에 최대 1,000행을 선택한다. 문서 잠금으로 동시 실행과 실행 중 설정 변경을 차단한다.
예상하지 못한 강제 종료도 이미 저장한 앞 행을 되돌리지는 않는다.

설정과 사용량
제공사별 키를 따로 저장하므로 Gemini 잔액을 사용하면서 OpenAI 키를 나중에 추가할 수 있다.
모델 목록 조회는 유지했다. 제공사별 저장 모델 ID는 보존하지만 전용 메뉴의 실행 모델은 고정된다.
향후 메뉴 모델을 바꾸려면 Code.gs 상단 RUN_PROFILES의 model을 수정한다.
Gemini 3.8과 GPT-6 Sol은 LOW 사고 수준을 사용한다. 최신 API에 맞춰 temperature를 보내지 않는다.
Claude 키·모델 관리와 호출 함수도 보존했지만 기본·Sol 메뉴에서 Claude를 호출하지 않는다.
'최근 실행 API 사용량'에는 요청·응답 모델, 입력·캐시 입력·출력·사고 토큰,
내용 검증·근거 부족 반려·보정·문장 축약 횟수를 표시한다.
출력 토큰에 사고 토큰이 포함되므로 둘을 다시 더하면 중복 계산이다.
사고 세부 수치가 없으면 0으로 확정하지 않고 미보고 횟수를 표시한다.
사용량 기록에는 API 키, 원문, 근거 인용을 저장하지 않는다.
Codex/ChatGPT 구독과 Apps Script의 OpenAI API 비용은 별개이다.
Gemini API는 Google 프로젝트, Sol API는 OpenAI 결제 계정의 요금과 한도에 따른다.
잔액·과거 사용량·최종 청구액은 제공사 콘솔에서 확인한다.

검증과 적용 범위
node tests/regression.cjs
유료 API를 호출하지 않는 48개 회귀 검증을 통과했다.
단어 손상, 바이트 상한, 수식 보존, 강제 비움, 재개 모델 유지, 선택 행 처리,
동일 프롬프트, 근거 없는 인용·주장 반려, 검증 누락, 백업 실패 시 기존 결과 보존을 확인했다.
실제 모델이 어떤 한국어 세특을 만드는지까지 모의 테스트로 증명한 것은 아니다.
유료 API 실호출과 구글 시트 설치는 아직 하지 않았다.
